# 키워드 목록

`python tests/keyword/catalog.py --write` 로 생성한 문서입니다. 키워드를 추가하면 이 파일도 다시 생성하세요 (일치 여부는 테스트가 확인합니다).

## admin_area (꽃가루·자외선 지역코드)

| 키워드 | 인자 | 설명 |
|---|---|---|
| `꽃가루_지역을_조회한다` | 위도, 경도 | 꽃가루용 지역코드를 조회하고 결과를 저장한다. |
| `꽃가루_지역을_확인한다` | 코드, 이름 | 꽃가루용 조회 결과(코드, 이름)가 기대와 같은지 확인한다. 코드가 빈 문자열이면 조회 실패를 뜻한다. |
| `자외선_지역을_조회한다` | 위도, 경도 | 자외선지수용 지역코드를 조회하고 결과를 저장한다. |
| `자외선_지역을_확인한다` | 코드, 이름 | 자외선지수용 조회 결과(코드, 이름)가 기대와 같은지 확인한다. |
| `지역파일을_더_읽을_수_없다` | - | 이미 읽어 둔 지역코드표가 사라진 상황을 만든다 (이후 읽기도 성공하지 못함). |
| `캐시된_지역코드를_확인한다` | 값 | 공용 캐시에 들어 있는 지역코드가 기대와 같은지 확인한다. 값이 null 이면 캐시가 비어 있어야 한다. |
| `코디네이터를_준비한다` | - | 지역코드표를 실제 파일에서 읽을 수 있는 코디네이터를 준비한다. |

## airkorea (에어코리아 대기질)

| 키워드 | 인자 | 설명 |
|---|---|---|
| `결과_값을_확인한다` | 키, 값 | 조회 결과의 특정 키 값이 기대와 같은지 확인한다. |
| `결과를_확인한다` | 값 | 조회 결과가 기대 딕셔너리와 정확히 같은지 확인한다. |
| `결과에_키가_없다` | 키 | 조회 결과에 특정 키가 없는지 확인한다. |
| `경고_횟수를_확인한다` | 횟수 | WARNING 이상 로그가 정확히 기대 횟수만큼 남았는지 확인한다. |
| `대기질_API가_응답한다` | 결과 | 대기질 조회 API 의 응답을 정한다: 정상 / 비어있음 / 실패. |
| `대기질을_조회한다` | 위도, 경도 | 지정한 위치의 대기질(_get_air_quality)을 조회하고 결과를 저장한다. |
| `에어코리아_API_호출_횟수를_확인한다` | 종류, 횟수 | 측정소 조회 / 대기질 조회 API 중 지정한 종류가 기대 횟수만큼 호출됐는지 확인한다. |
| `에어코리아_호출은_긴_타임아웃과_DEBUG_로그를_쓴다` | 호출수 | 에어코리아(B552584) 호출이 기대 횟수이고 모두 timeout=30, fail_log_level=DEBUG 인지 확인한다. |
| `에어코리아를_준비한다` | - | 가짜 에어코리아 API 를 준비한다. 처음엔 모든 호출이 실패하고 측정소코드 확보·페이지 보완도 못 하는 상태. |
| `주소_조회_결과가_비어_있다` | - | 역지오코딩 결과에 시/구/동 정보가 없어 주소가 빈 문자열이다. |
| `측정소_조회가_응답한다` | 결과 | 측정소 조회 API 의 응답을 정한다: 정상(화랑로) / 강남(강남 측정소) / 실패 / 미신청. |
| `측정소가_캐시되어_있다` | 이름, 코드, 위도, 경도 | 이전 주기에 확보한 측정소 이름·코드와 그때의 위치를 캐시에 넣는다. |
| `측정소코드_확보_호출을_확인한다` | 횟수, 인자 | 측정소코드 확보가 기대 횟수만큼 불렸는지(인자가 있으면 그 인자로) 확인한다. |
| `측정소코드_확보가_성공한다` | 코드 | 에어코리아 페이지에서 측정소코드를 확보하는 데 성공해 지정한 코드를 돌려준다. |
| `캐시된_측정소를_확인한다` | 이름, 코드, 위도, 경도 | 캐시된 측정소 이름·코드(와 위치)가 기대와 같은지 확인한다. 이름이 null 이면 이름 캐시가 비어 있어야 한다. |
| `페이지_보완_호출을_확인한다` | 횟수, 코드 | 페이지 보완 조회가 기대 횟수만큼 불렸는지(코드가 있으면 그 코드로) 확인한다. |
| `페이지_보완이_성공한다` | - | 에어코리아 페이지 보완 조회가 성공해 미세먼지 30, 초미세먼지 12, 오존 0.020 을 돌려준다. |

## area_codes (구역코드 결정·캐시)

| 키워드 | 인자 | 설명 |
|---|---|---|
| `구역코드_코디네이터를_준비한다` | - | 구역코드 표를 읽어 두고, 구역코드를 결정할 코디네이터를 준비한다. |
| `구역코드는_다섯_개_값이다` | - | 가장 최근 결과가 (nx, ny, 기온구역, 육상구역, 특보구역) 다섯 개이고 격자는 정수, 나머지는 비어 있지 않은지 확인한다. |
| `구역코드를_결정한다` | 위도, 경도 | 좌표로 구역코드를 결정하고 결과를 차례대로 저장한다 (2km 안이면 캐시를 재사용). |
| `구역코드를_확인한다` | 기온구역, 육상구역, 특보구역 | 가장 최근 결과의 기온구역·육상구역·특보구역이 기대와 같은지 확인한다. |
| `직전과_같은_결과다` | - | 가장 최근 결과가 직전 결과와 완전히 같은지(캐시 재사용) 확인한다. |
| `직전과_특보구역이_다르다` | - | 가장 최근 결과의 특보구역이 직전 결과와 다른지(재계산) 확인한다. |
| `캐시가_비어_있다` | - | 아직 구역코드를 결정한 적이 없어 좌표·특보구역 캐시가 모두 비어 있는지 확인한다. |
| `캐시된_좌표_위도를_확인한다` | 위도 | 캐시에 기억된 기준 위도가 기대와 같은지 확인한다 (캐시 재사용이면 최초 좌표, 재계산이면 새 좌표). |

## pause_zone (일시정지 존)

| 키워드 | 인자 | 설명 |
|---|---|---|
| `API_호출횟수를_확인한다` | 횟수 | 지금까지 API(fetch_data)가 호출된 횟수가 기대와 같은지 확인한다. |
| `기기를_등록한다` | 존 | 모바일 기기(device_tracker)를 등록하고 지정한 존을 pause_zones 로 설정한다. 처음엔 집 안, 시각은 10:00. |
| `시간이_흐른다` | 분 | 가상 시계를 분 단위로 진행하고, 대기 시간이 끝난 예약이 있으면 실행한다. |
| `예약된_대기가_있는지_확인한다` | 있음 | 존 이탈 후 5분 대기 예약이 남아 있는지(있음/없음) 확인한다. |
| `위치를_이동한다` | 장소 | 기기의 위치를 '집' 또는 '집 밖'으로 옮기고 위치 변화 이벤트를 발생시킨다. |
| `정기업데이트가_실행된다` | 결과 | 매시 :15 정기 업데이트를 실행한다. 결과가 '실패'이면 API 가 빈 응답을 돌려준다. |
| `존_안_상태를_확인한다` | 안 | 코디네이터가 기억하는 '존 안/밖' 상태가 기대와 같은지 확인한다. |
| `현재시각을_설정한다` | 시, 분 | 가상 시계를 오늘(2026-10-19) 시:분으로 맞춘다. |

## precip (예상 강수량)

| 키워드 | 인자 | 설명 |
|---|---|---|
| `상태값을_확인한다` | 값 | 센서 상태값(precip_amount)이 기대와 같은지 확인한다. |
| `속성_키가_하루_전체인지_확인한다` | - | 속성 키가 항상 '00시'~'23시' 24개이고 시간 순서인지 확인한다. |
| `속성값을_확인한다` | 키, 값 | 시간대별 속성(예: '15시')의 값이 기대와 같은지 확인한다. 지난 시간은 '-'. |
| `시각을_맞추고_갱신한다` | 시, 분, 일 | 가상 시각(2026-10 {일}일 시:분)으로 갱신(_merge_all)을 실행하고 결과를 저장한다. |
| `예보를_준비한다` | 강수량, 눈, 첫슬롯시, 일수 | 단기예보를 준비한다. 강수량은 {시: 원본값}, 눈은 {시: 적설 원본값}, 첫슬롯시는 발표본의 첫 시각. |
| `한시간이_지나고_갱신한다` | - | 직전 갱신으로부터 1시간 뒤 시각으로 다시 갱신한다. |
